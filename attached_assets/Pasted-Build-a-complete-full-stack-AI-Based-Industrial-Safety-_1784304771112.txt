Build a complete full-stack AI-Based Industrial Safety Monitoring System with a React.js + Tailwind CSS frontend, FastAPI backend, MongoDB database, and REST APIs. The application should open to a login page, followed by a modern industrial dashboard with a dark professional UI. The dashboard should contain a large Live Camera Monitoring section displaying real-time video feeds from multiple cameras with AI detection overlays. Each detected worker should have a bounding box showing a Track ID, RFID Employee ID (if available), helmet status, safety vest status, face mask status, and whether the worker is currently inside a Safe Zone or a Hazard/Work Zone. Beside the live monitoring panel, display real-time statistics including total workers detected, workers inside hazard zones, helmet compliance, vest compliance, mask compliance, active violations, and current worker count. The dashboard should also continuously display real-time IoT sensor values such as temperature, gas level, humidity (optional), and indicate whether the environment is Safe, Warning, or Critical. Create a Safety Zone management module where administrators can define polygon-based hazard zones for each camera and configure the mandatory PPE required for each zone (helmet, vest, mask). The system should only generate alerts when a worker enters a hazard zone without the required PPE; workers outside the hazard zone should not trigger any violation. When a PPE violation is detected, automatically capture a snapshot of the worker, save the image along with timestamp, camera ID, zone name, Track ID, RFID ID, missing PPE information, and alert status into a MongoDB Warning Log collection. The dashboard should immediately display the alert in a live warning panel and send a real-time notification using WebSockets. Integrate RFID support by assuming every worker carries a unique RFID tag or ID card, and associate the latest RFID reading from that work zone with the detected worker whenever possible. Implement an audio alert system using Text-to-Speech so that when a violation occurs, the system announces a personalized warning such as: 'Attention Employee RFID 102. You have entered the Welding Zone without wearing a safety helmet. Please wear your safety helmet immediately.' or 'Attention Employee RFID 115. Safety vest is missing. Please wear your safety vest before continuing work.' The voice announcement should repeat until the violation is resolved or acknowledged by the supervisor. Create dedicated pages for Workers, Cameras, Safety Zones, Alerts, Warning Logs, Reports, Sensor Monitoring, and Settings. The Workers page should display RFID, Employee Name, Current Zone, PPE Status, Last Seen, and Compliance History. The Cameras page should support CRUD operations and camera-to-zone mapping. The Alerts page should allow supervisors to acknowledge, resolve, filter, and search alerts while viewing captured snapshots. The Reports page should include analytics for daily, weekly, and monthly PPE violations, compliance percentages, zone-wise violations, worker-wise violations, sensor history, and downloadable PDF/Excel reports. The Sensor Monitoring page should display live temperature and gas graphs with threshold configuration. The Settings page should allow configuring factory information, voice alert language, alert thresholds, RFID integration, sensor thresholds, camera settings, and notification preferences. Structure the backend with FastAPI using modular APIs, MongoDB collections for Users, Workers, Cameras, Safety Zones, Sensors, Alerts, Warning Logs, Reports, and Settings. Use mock data initially for camera feeds, RFID readings, YOLO detections, ByteTrack IDs, and sensor values so the entire application is fully functional without requiring actual AI models. Organize the project with clean architecture, reusable React components, responsive UI, Lucide React icons, loading skeletons, toast notifications, protected authentication, WebSocket-based live updates, and clear API integration points so YOLOv8, ByteTrack, OpenCV, ESP32 sensor data, and RFID hardware can be integrated later without changing the frontend architecture.
